# 🔐 ระบบสมาชิก (Member System)

ระบบสมัครสมาชิก / ยืนยันตัวตน / จัดการบัญชี สำหรับนำไปต่อยอดเป็นระบบอื่น ๆ
สร้างด้วย **Node.js + Express + MySQL** (ไม่ต้องใช้ Python)

## ✨ ฟีเจอร์

### สมัครสมาชิก (`register.html`)
- กรอกอีเมล รหัสผ่าน ยืนยันรหัสผ่าน เบอร์โทรศัพท์
- ✅ ตรวจรูปแบบอีเมล + **ปุ่มตรวจสอบอีเมลซ้ำ** (เรียก API real-time)
- ✅ ตัววัดความแข็งแรงรหัสผ่าน (ต้อง ≥ 8 ตัว และผ่าน ≥ 3 เกณฑ์)
- ✅ ตรวจเบอร์โทรไทย (มือถือขึ้นต้น 06/08/09) — **ลูกค้าลืม 0 นำหน้าก็ได้** (`812345678`, `912345678`) และพิมพ์ `+66`/`66` มาก็ได้ ระบบจะแปลงเป็น `0XXXXXXXXX` ให้เองทั้งฝั่งหน้าเว็บและเซิร์ฟเวอร์ (`src/lib/validators.js` → `normalizeThaiPhone`)
- ✅ บังคับยอมรับข้อกำหนด PDPA + honeypot + ตรวจเวลากรอกฟอร์ม + rate limit ต่อ IP
- 🔒 รองรับ **Google reCAPTCHA v2** (เปิดเมื่อตั้ง key)

### ยืนยันตัวตนด้วย OTP (ในหน้า `register.html` ทั้งหมด)
- กรอกฟอร์ม → กด **"ขอ OTP"** ที่ช่องเบอร์โทร → ช่องกรอกรหัส 6 หลักโผล่ในหน้าเดียวกัน (เลื่อนช่องอัตโนมัติ)
- ปุ่ม **"สมัครสมาชิก"** กดได้เมื่อกรอกรหัสครบ 6 หลักเท่านั้น
- กดสมัคร → ยืนยันรหัส SMS แล้ว **ส่งรหัส OTP ไปทางอีเมล** ให้กรอกในขั้นถัดไป (แทนลิงก์ยืนยันแบบเดิม)
- ยืนยันอีเมลครบ → บัญชีพร้อมใช้งานและล็อกอินอัตโนมัติ
- นับถอยหลัง 60 วินาทีก่อนส่งรหัสใหม่ / กรอกผิดได้ 5 ครั้ง / อายุรหัส 5 นาที
- ส่ง SMS จริงผ่าน **Twilio** หรือ **ThaiBulkSMS** / อีเมลผ่าน SMTP (โหมด dev แสดงรหัสบนหน้าจอ)

### ยืนยันอีเมล
- ใช้ **รหัส OTP 6 หลักทางอีเมล** ตอนสมัครสมาชิก (บัญชีเดิมที่ยังไม่ยืนยันยังใช้ลิงก์ยืนยันที่หน้าบัญชีได้)

### เข้าสู่ระบบ / ออกจากระบบ (`login.html`)
- ล็อกอินด้วยอีเมล + รหัสผ่าน → ล็อกอินอัตโนมัติหลังยืนยัน OTP
- session เก็บในคุกกี้ `httpOnly` SameSite=Lax

### เข้าสู่ระบบด้วย Google (`login.html` → ปุ่ม Google)
- ครั้งแรก: พาไปหน้า `google-setup.html` ตั้งรหัสผ่าน + เบอร์โทร + ยืนยัน OTP
- อีเมลตรงบัญชีเดิม → เข้าบัญชีนั้นทันที
- อีเมลถือว่ายืนยันแล้ว (Google ยืนยันให้)
- โหมดทดสอบ (dev): ยังไม่มี `GOOGLE_CLIENT_ID` → ปุ่ม Google ไปหน้า mock กรอกอีเมลจำลอง

### ลืมรหัสผ่าน (`forgot.html`)
- 3 ขั้นตอน: กรอกอีเมล → ยืนยัน OTP ทางอีเมล → ตั้งรหัสใหม่
- กัน spam (60 วินาที/ครั้ง) + ตอบเหมือนกันแม้อีเมลไม่มีในระบบ + ออกจากระบบทุกเครื่องหลังเปลี่ยนรหัส

### หน้าบัญชี (`/settings/profile`, `/settings/security`)
- **โปรไฟล์**: ข้อมูลผู้ใช้ + สถานะยืนยันเบอร์/อีเมล + ปุ่มส่งลิงก์ยืนยันอีเมลใหม่ + ลิงก์เข้าระบบหลังบ้าน (แอดมิน/เจ้าของระบบ)
- **ความปลอดภัย**: เปลี่ยนรหัสผ่าน (ตรวจรหัสเดิม) + ออกจากระบบทุกเครื่อง + ออกจากระบบ
- **ข้อมูลส่วนบุคคลของฉัน (PDPA)** `/settings/privacy` — สิทธิของเจ้าของข้อมูลตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 ใช้ได้เองจากหน้าเว็บ: ดู**สถานะความยินยอม** (ยอมรับนโยบายเวอร์ชันใด เมื่อวันเวลาใด — ระบบบันทึกไว้เป็นหลักฐาน), **ดาวน์โหลดสำเนาข้อมูล** (`GET /api/me/export` ได้ไฟล์ JSON ของบัญชี + ประวัติการซื้อ + ข้อมูลร้าน/บิล ถ้ามี) และ **ลบบัญชีของฉัน** (ปุ่มยืนยันด้วยรหัสผ่าน + พิมพ์คำว่า “ลบบัญชี” → ลบข้อมูลถาวรทันที; บัญชีผู้ดูแลระบบลบเองไม่ได้)
- **บนจอมือถือ เมนูด้านซ้ายของหน้านี้เป็น “แผงเลื่อนออกจากด้านซ้าย”** เหมือนหน้าโซนร้านค้า — เปิด/ปิดด้วยปุ่ม ☰ (แตะฉากมืดหรือกด Esc เพื่อปิด, จำค่าไว้ในเครื่อง) เนื้อหาจึงเริ่มติดแถบหัวทันที ส่วนจอใหญ่เห็นเมนูค้างด้านซ้ายตลอด
- **ปุ่มออกจากระบบมีที่หน้าโปรไฟล์นี้เท่านั้น** — ในหน้าของโซนร้านค้า (`/shop/*`) แถบเมนูด้านบนมีปุ่ม **“ออกจากร้านค้า”** ซึ่งพากลับมาที่หน้าโปรไฟล์ (`/settings/profile`) ไม่ได้ล็อกเอาต์ทันที กันกดพลาดแล้วหลุดจากระบบกลางทาง

### ระบบหลังบ้าน (`/admin/`) — แอดมินและเจ้าของระบบ
- **ตารางข้อมูลบนมือถือ: ทุกช่องของแต่ละแถวอยู่บรรทัดเดียวกัน** — ตารางกว้างตามเนื้อหาแล้วเลื่อนซ้าย-ขวาในกรอบแทนการบีบข้อความจนตัดบรรทัด (รวมช่องอีเมลและกลุ่มปุ่มในคอลัมน์จัดการ)
- **เมนูด้านซ้าย** ใช้ร่วมกันทุกหน้า (ภาพรวม / จัดการ SMS-OTP / ผู้ใช้งาน / แพ็กเกจร้านค้า / การชำระเงิน / ประวัติการซื้อ / ตั้งค่าหน้าเว็บไซต์ / ข้อมูลทางกฎหมาย (PDPA) / เปิดหน้าเหมือนผู้ใช้ / ออกจากระบบ) และบน**จอมือถือเป็นแผงเลื่อนออกจากด้านซ้าย** เปิด/ปิดด้วยปุ่ม ☰ (แตะฉากมืดหรือกด Esc เพื่อปิด, จำค่าไว้ในเครื่อง) เหมือนหน้า `/shop` และ `/settings`
  - เมนูที่เรนเดอร์จากฝั่งเซิร์ฟเวอร์ถูกแทรกที่จุดแทนที่ `<!--MENU_ROLE-->` โดยดูรายการ + สิทธิ์จาก `ADMIN_MENUS` ใน `src/routes/admin-pages.js` (`ownerOnly: true` = เฉพาะเจ้าของระบบ) — **เพิ่มหน้าใหม่ต้องใส่ชื่อไฟล์ใน `PAGES` ด้วย** ไม่งั้นจะไม่ถูกส่งผ่านเส้นทางนี้
- **ภาพรวม**: สถิติผู้ใช้ + OTP ล่าสุด + สรุปข้อมูลทางกฎหมาย (ชื่อผู้ให้บริการ/อีเมลติดต่อ) พร้อมปุ่มลัดไปหน้าตั้งค่า
- **จัดการ SMS-OTP**: สถานะระบบ, ตั้งค่าอายุรหัส/จำนวนครั้ง, สลับ dev mode (ไม่ต้องรีสตาร์ท), ตั้งค่า SMS จริง + ทดสอบ, ตั้งค่า SMTP + ทดสอบ, รายการ OTP + ส่ง OTP ใหม่
- **จัดการผู้ใช้**: ค้นหา/แก้ไข/ลบ — **เบอร์โทรที่แสดงจะเติม 0 นำหน้าให้อัตโนมัติ** ถ้าข้อมูลเดิมบันทึกไว้โดยไม่มี 0 (`displayThaiPhone` ใน `src/lib/validators.js`) และตอนบูตระบบมี migration ครั้งเดียวเติม 0 ลงฐานข้อมูลจริงสำหรับเบอร์ 9 หลักที่ขึ้นต้น 6/8/9 (`legacy_phone_zero_filled` ใน `initDb`)
- **ตั้งค่าหน้าเว็บไซต์** (`/admin/site.html`, แอดมิน+เจ้าของระบบ): ช่องทางโซเชียล **Facebook / LINE** ที่แสดงเป็นไอคอนท้ายหน้าเว็บหลัก (`/`) — **กรอกช่องไหนจึงขึ้นช่องนั้น** ไม่กรอก = ไม่แสดงเลย · กรอกได้ทั้งลิงก์เต็ม, `facebook.com/ชื่อเพจ`, ชื่อเพจเปล่า ๆ, `lin.ee/xxx`, `@ไอดีทางการ`, `~ไอดีส่วนตัว` (ระบบแปลงเป็นลิงก์ให้ และโชว์ตัวอย่างปุ่มจริงในหน้าตั้งค่าก่อนบันทึก) · ค่าเก็บใน `settings` (`site_facebook_url`, `site_line_url`) อ่านผ่าน `GET /api/public/site` · ค่าที่จะใส่ใน `href` ถูกตรวจว่าเป็น `http/https` เท่านั้น (กัน `javascript:`)
- **ข้อมูลทางกฎหมาย (PDPA)** (`/admin/legal.html`, เจ้าของระบบ): ชื่อผู้ให้บริการ + อีเมลติดต่อเรื่องข้อมูลส่วนบุคคล ที่แสดงในหน้า `/privacy.html` ข้อ 11 — แก้ได้ไม่ต้องรีสตาร์ท มีตัวอย่างข้อความจริงให้ดูก่อนบันทึก (ผู้ดูแลระบบที่ไม่ใช่เจ้าของเปิดดูได้แต่แก้ไม่ได้)
- ตรวจสิทธิ์ `role = admin` หรือ `owner` — คนที่ไม่มีสิทธิ์ (ผู้ใช้ทั่วไป/เจ้าของร้าน) จะถูก **พาไปหน้าโปรไฟล์ของตัวเองอัตโนมัติ** ไม่แสดงหน้า 403 ให้เห็น (ถ้ายังไม่ล็อกอิน → ไปหน้าล็อกอินพร้อม `next`) ส่วนหน้าที่สงวนไว้ให้ `owner` ถ้าเปิดโดย `admin` จะพากลับ `/admin/` — **API ยังตอบ 403 เป็น JSON ตามเดิม**

## 👥 บทบาทผู้ใช้ (owner > admin > shop > user)

| บทบาท | สิทธิ์ |
|---|---|
| `owner` | เจ้าของระบบ (สูงสุด) — เข้าได้ทุกอย่างที่แอดมินเข้าได้ + จัดการบัญชี `admin`/`owner`/`shop` (ตั้ง/ถอดบทบาท, ลบ) |
| `admin` | แอดมินแพลตฟอร์ม — จัดการผู้ใช้ทั่วไป + ตั้งค่าระบบ (SMS/SMTP/OTP) — แตะบัญชี `admin`/`owner` ไม่ได้ |
| `shop` | เจ้าของร้าน (ผู้ซื้อแพ็กเกจ) — จัดการร้าน/เมนูของตัวเองเท่านั้น **เข้า `/admin` ของแพลตฟอร์มไม่ได้** |
| `user` | ผู้ใช้ทั่วไป (ซื้อแพ็กเกจเพื่อเปิดร้านได้) |

- บัญชีแรกสร้างอัตโนมัติตอน boot ด้วย `ADMIN_EMAIL`/`ADMIN_PASSWORD` (ค่าเริ่มต้นเป็นบทบาท `owner`)
- ระบบกันไม่ให้เหลือ `owner` น้อยกว่า 1 คน และห้ามลดบทบาท/ลบตัวเอง
- ฐานข้อมูลเดิมที่มี `admin` อยู่แล้วแต่ยังไม่มี `owner` ระบบจะยกระดับแอดมินคนแรกเป็น `owner` ให้ครั้งเดียว

## 🍜 ระบบร้านค้า / ร้านอาหาร (เฟสแรก)

- **ผู้ใช้ทั่วไป** เปิดร้านด้วยการซื้อแพ็กเกจ (จำลอง) ที่ `/shop` → ได้บทบาท `shop` อัตโนมัติ
- **ในโซนร้านค้า (`/shop/*`) แถบหัวใช้ “โลโก้ร้าน + ชื่อร้าน”** (ถ้าร้านยังไม่มีโลโก้จะใช้โลโก้ QPage เดิม) — นอกโซนนี้ (หน้าแรก/เข้าสู่ระบบ/โปรไฟล์) ยังเป็นโลโก้ QPage เหมือนเดิม
- **ชื่อร้านในแถบหัวถูกใส่มาจากเซิร์ฟเวอร์ตั้งแต่แรก** — เปิด/รีเฟรชหน้าแล้วเห็นชื่อร้านจริงทันที ไม่มีคำว่า “ร้านของฉัน” ขึ้นแวบก่อน JS โหลดเสร็จ (ดู `src/lib/shop-page.js`)
- **เมนูลัดของโซนร้านค้าอยู่เป็น “แถบด้านซ้าย”** (สไตล์เดียวกับเมนูหน้า `/settings`) ในทุกหน้า `/shop/*`: สั่งอาหาร · ครัว · แคชเชียร์ · ประวัติ · จัดการเมนู · เมนูทั้งหมด · ตั้งค่าข้อมูลร้าน · แจ้งเตือน · **ตั้งค่าระบบ** · ดูร้าน (เปิดแท็บใหม่) และปุ่มล่างสุด “ออกจากร้านค้า” (กลับหน้าโปรไฟล์) — ไฮไลต์เมนูของหน้าที่เปิดอยู่ให้อัตโนมัติ — **บนจอมือถือเมนูเป็น “แผงเลื่อนออกจากด้านซ้าย”** เปิด/ปิดด้วยปุ่ม ☰ (ใช้เมนูชุดเดียวกัน ไม่ใช่เมนูคนละแบบ) — ปิดไว้แล้วเมนูเลื่อนหายไปทางซ้าย เนื้อหาไม่ถูกดันลงด้านล่าง, เปิดแล้วมีฉากมืดด้านหลังให้แตะปิด (หรือกด Esc ก็ได้) เริ่มจากซ่อนไว้ให้เห็นเนื้อหาก่อน และจำค่าที่เลือกไว้ในเครื่อง ส่วนจอใหญ่เห็นเมนูค้างด้านซ้ายตลอดเวลา
- **เจ้าของร้าน** ตั้งข้อมูลร้าน (`/shop/setup.html`): **โลโก้ร้านเป็นช่องแรก** (ใช้เป็นรูปในการ์ดพรีวิวเวลาแชร์ลิงก์ด้วย), ชื่อร้าน, เบอร์ติดต่อ, ลิงก์ LINE, URL Google Maps และ **เนื้อหา SEO** (หัวข้อ SEO + คำอธิบาย SEO) พร้อม **ตัวอย่างการ์ดเวลาแชร์ลิงก์** ที่อัปเดตทันทีขณะพิมพ์ — ไม่มีปุ่ม “ไปหน้าจัดการเมนู” แล้ว (เข้าได้จากเมนูด้านซ้ายตามปกติ)
- **จัดการเมนู** (`/shop/menu.html`): หมวดหมู่ + หมวดหมู่ย่อย, ฟอร์มเพิ่ม/แก้ไขเมนู (ชื่อ + รูป + ราคา + รายละเอียด + เปิด/ปิดขาย + ติ๊กผูกกลุ่มตัวเลือก), กลุ่มตัวเลือกและตัวเลือก (เช่น ระดับความเผ็ด, ทานที่ร้าน/ห่อกลับบ้าน) — **รายการเมนูที่เพิ่มไว้ย้ายไปหน้า “เมนูทั้งหมด”** (ดูข้อถัดไป) โดยในหน้านี้มีปุ่ม **“ดูเมนูทั้งหมด”** (ปุ่มไล่สีพร้อมไอคอน อยู่แถวเดียวกับหัวข้อ “จัดการเมนู”) เปิดตารางเมนู และรับ `?edit=<id>` เพื่อโหลดเมนูนั้นกลับมาแก้ในฟอร์มทันที
- **เมนูทั้งหมด** (`/shop/menus.html`) — ตารางแบบเอ็กเซล: หัวตารางตรึงด้านบน มีเส้นตารางและแถวสลับสี, คอลัมน์ # / รูป / ชื่อเมนู (+รายละเอียด) / หมวดหมู่ (แสดง “หมวด › หมวดย่อย”) / ราคา / ตัวเลือกที่ใช้ / สถานะ / จัดการ — **ตัวกรองหมวดหมู่ 2 ชั้นแบบแถวเดียว** (ไม่ต้องเปิด dropdown) — แถวแรกเป็น **หมวดหมู่หลัก** (ปุ่มแรกชื่อ “ทั้งหมด”) กดเลือกแล้วจะเห็น **เมนูทั้งหมดของหมวดนั้นรวมถึงเมนูในหมวดย่อยทุกตัว** และถ้าหมวดหลักนั้นมีหมวดย่อย จะมี **แถวที่สองโผล่ขึ้นมาให้เจาะจงหมวดย่อย** (**ทุกปุ่มในแถวนี้เป็นสีเหลือง** — ปุ่มแรกชื่อ “ทั้งหมด” ใช้กลับไปดูทั้งหมวด ส่วนแถวหมวดหลักเป็นสีม่วง) ทั้งสองแถวเลื่อนซ้าย-ขวาได้เมื่อมีหลายหมวด และ**บนปุ่มกรองมีตัวเลขกำกับจำนวนเมนูของหมวดนั้น** (นับยอดรวมของหมวด ไม่เปลี่ยนตามคำค้น/ตัวกรองอื่น), แถบเครื่องมือ (ช่อง**ค้นหา**, ตัวกรอง**สถานะ**, **ออกรายการ CSV**, **＋ เพิ่มเมนูใหม่**) อยู่บรรทัดเดียวกับหัวเรื่อง, **เรียงลำดับได้โดยกดที่หัวคอลัมน์** (ชื่อเมนู / หมวดหมู่ / ราคา / สถานะ / # — กดซ้ำเพื่อสลับ น้อย→มาก / มาก→น้อย; ค่าเริ่มต้นเรียงตามหมวดหมู่ → ชื่อ), **สลับ “พร้อมขาย” ได้ในตารางเลย**, ปุ่ม **＋ เพิ่มเมนูใหม่** และปุ่ม **แก้ไข** ใช้ **ป๊อปอัพเดียวกันในหน้านี้เลย** (โหมดเพิ่ม/แก้ไข) (ชื่อ / หมวดหมู่ / ราคา / รายละเอียด / รูป / พร้อมขาย / กลุ่มตัวเลือก) กรอกแล้วกด “เพิ่มเมนู”/“บันทึก” จบในหน้า ไม่ต้องเด้งไปหน้าจัดการเมนู (ตอนเพิ่มจะตั้งหมวดหมู่ให้ตามหมวดที่กำลังกรองอยู่ให้ด้วย) และปุ่มลบ พร้อมปุ่ม **ออกรายการเป็น CSV** (มี BOM เปิดใน Excel อ่านภาษาไทยได้)
- **มาร์คตัวเลือกเป็น "ค่าเริ่มต้น" (⭐)** — ในหน้าจัดการเมนู ส่วน "กลุ่มตัวเลือกในเมนู" กดดาวที่ตัวเลือกเพื่อมาร์ค/ยกเลิก ตัวเลือกที่มาร์คไว้จะ **ถูกเลือกให้อัตโนมัติเมื่อลูกค้าเลือกเมนูที่ใช้กลุ่มนั้น** (และในหน้าต่าง "เพิ่มอาหาร" ของแคชเชียร์ด้วย) — กลุ่มที่ **เลือกได้อย่างเดียว** มีค่าเริ่มต้นได้ทีละตัว (มาร์คตัวใหม่จะยกเลิกตัวเดิมอัตโนมัติ) ส่วนกลุ่มที่ **เลือกได้หลายอย่าง** มาร์คได้หลายตัว ถ้าลูกค้าเคยเลือกเองไว้แล้ว ระบบจะไม่ทับด้วยค่าเริ่มต้น
- **หน้าร้านสาธารณะ** `/s/:code` — ลูกค้าเปิดดูโลโก้/ชื่อ/เมนูแยกหมวดพร้อมตัวเลือก (ไม่ต้องล็อกอิน) และ **ช่องทางติดต่อร้านแสดงเป็นปุ่มกลมมีไอคอน** (ไม่ใช้อิโมจิ): **เบอร์โทรร้าน** (กดโทรออกได้ทันที), **LINE ร้านค้า** (ปุ่มสีเขียวแบรนด์ เปิดแชท) และ **ดูแผนที่** (เปิด Google Maps) — **จัดเป็น 2 แถวชิดขอบขวาของแบนเนอร์ร้าน: แถวบน LINE · แถวล่าง เบอร์โทรร้าน + แผนที่** ปุ่มขนาดเล็กกะทัดรัด แสดงเฉพาะช่องที่ร้านกรอกไว้ · **บนจอมือถือย่อทุกอย่างให้กะทัดรัด** (ปุ่มไม่ยืดเต็มความกว้าง + ปกเตี้ยลง: padding 22px, โลโก้ 68px) · หน้าสั่งอาหารของลูกค้า `/order/:token` ใช้ปุ่มชุดเดียวกันนี้
  - หมายเหตุสำหรับคนแก้ CSS: กฎ `@media (max-width: 560px)` ของหน้าลูกค้าต้องอยู่ **หลัง** กฎหลักในไฟล์ (ท้ายไฟล์) ไม่งั้นจะถูกกฎหลักที่อยู่บรรทัดล่างกว่าทับ เพราะ CSS เลือกจากลำดับในไฟล์เมื่อความจำเพาะเท่ากัน
- **SEO / การ์ดพรีวิวเวลาแชร์ลิงก์ร้าน** — เสิร์ฟเวอร์อ่านข้อมูลร้านแล้วแทรก `<meta>` ลงในหน้า `/s/:code` **ตั้งแต่ HTML ที่ตอบกลับ** (ไม่รอ JS) ที่จุดแทนที่ `<!--SHOP_SEO-->` โดย `src/lib/shop-seo.js`:
  - `title` / `description` / `canonical` / `robots: index,follow` + **Open Graph** (`og:title`, `og:description`, `og:image`, `og:url`, `og:type=restaurant.restaurant`) + Twitter card → **ส่งลิงก์ร้านในแชท LINE/Facebook แล้วขึ้นการ์ดมีโลโก้ร้าน + ชื่อร้าน + ข้อความ SEO**
  - **JSON-LD** (`schema.org/Restaurant`: ชื่อ, รูป, เบอร์โทร, ลิงก์แผนที่, LINE) ช่วยให้ Google เข้าใจว่าเป็นหน้าร้านอาหาร
  - ใช้ค่าที่ร้านกรอกไว้ (`shops.seo_title`, `shops.seo_description`) ถ้าเว้นว่างระบบสร้างจากชื่อร้าน/เบอร์โทรให้เอง · ร้านที่ไม่มีอยู่จริง/ปิดอยู่จะได้ `noindex`
  - `og:image` ต้องเป็น URL เต็ม — ประกอบจาก `req.protocol + host` (มี `trust proxy` อยู่แล้ว จึงออกเป็น https:// ถูกต้องหลัง Nginx)
- **ให้ Google ค้นเจอชื่อร้าน** — `src/routes/seo.js` ให้ `/robots.txt` (เปิดให้เก็บหน้าแรก/สมัคร/นโยบาย/หน้าร้าน `/s/…` และปิดพื้นที่ส่วนตัว `/admin`, `/settings`, `/shop`, `/api/`) และ `/sitemap.xml` ที่ **สร้างจากรายชื่อร้านจริงในฐานข้อมูล** (อัปเดตเองอัตโนมัติเมื่อมีร้านใหม่) — วิธีทำให้ขึ้นจริง: ยื่น `https://qpage.website/sitemap.xml` ที่ Google Search Console หนึ่งครั้ง (การจัดอันดับ/การขึ้นผลค้นหาเป็นดุลพินิจของ Google ใช้เวลาหลายวันถึงหลายสัปดาห์)
- **เบอร์ที่ลูกค้าเห็นคือ “เบอร์โทรร้าน”** — ตั้งได้ที่หน้า **ตั้งค่าข้อมูลร้าน** (`/shop/setup.html`) ช่อง “เบอร์โทรร้าน” (มีคำอธิบายกำกับว่าเป็นเบอร์ของร้านที่ลูกค้าเห็น ไม่ใช่เบอร์บัญชีผู้ใช้) · เพิ่มช่อง LINE/Google Maps ก็จะกลายเป็นปุ่มให้ลูกค้ากดในหน้าสั่งอาหาร
- **ของขวัญร้านค้า (owner)**: เจ้าของระบบมอบสิทธิ์เจ้าของร้านชั่วคราวให้ผู้ใช้ได้ที่หน้าจัดการผู้ใช้ (`/admin/users.html` → ปุ่ม 🎁) พร้อมกำหนดวันหมดอายุ — หมดอายุแล้วระบบถอนบทบาทกลับเป็น `user` และปิดหน้าร้านชั่วคราวให้อัตโนมัติ
- ยังไม่รวมตะกร้า/ออเดอร์ (อยู่เฟสถัดไป)

## 🍽️ ระบบสั่งอาหาร (QR ต่อโต๊ะ)

- **หน้าสั่งอาหารของร้าน** `/shop/orders.html` (เฉพาะเจ้าของร้าน) — สร้าง "โต๊ะ" โดยกรอกเลข/ชื่อโต๊ะเป็นตัวอักษรหรือตัวเลขได้ ระบบออกรหัส QR ให้อัตโนมัติ (ดาวน์โหลด/พิมพ์ได้)
- **ลูกค้าสแกน QR** → เปิดหน้า `/order/:token` (ไม่ต้องล็อกอิน) — **แต่ละเมนูมีช่องจำนวนเริ่มที่ 0** (กด −/+) และ **เมื่อมีรายการใดมากกว่า 0 จะมีปุ่ม "สั่งออเดอร์"** ให้กดส่งทั้งชุดในครั้งเดียว — **เมนูที่มีกลุ่มตัวเลือก จะเด้งหน้าต่างให้เลือกตัวเลือกอัตโนมัติเมื่อกด + ครั้งแรก** (กดซ้ำจะเพิ่มจำนวนเลย) — มี **แถบหมวดหมู่ใหญ่ด้านบน** ที่ **เลื่อนซ้าย-ขวาได้** (ติดอยู่ด้านบนขณะเลื่อน กดเพื่อกระโดดไปหมวดนั้น) และปุ่ม **"รายการทั้งหมด"** ในส่วนหัวสำหรับดูบิลของโต๊ะ (สถานะครัว + ยกเลิกรายการที่ยังไม่เริ่มทำ)
- **รวมเป็นบิลเดียวต่อโต๊ะ** — ทุกรายการที่ส่งมาจะต่อเข้าบิลที่เปิดอยู่ของโต๊ะนั้น จนกว่าร้านจะกด **เช็คบิล** (ปิดบิลแล้วเปิดบิลใหม่ว่างให้โต๊ะเดิมทันที)
- **ประตูร้าน `/shop`** — คลิก “ร้านค้าของฉัน” (จากหน้าบัญชี หรือปุ่มบนหน้าแรก) แล้วเข้าสู่โซนร้านค้า ระบบจะพาไป **หน้าสั่งอาหาร `/shop/orders.html` เป็นหน้าเริ่มต้น** — ถ้ายังไม่มีข้อมูลร้าน จะพาไปหน้าตั้งค่าข้อมูลร้าน (`/shop/setup.html`) ก่อน (ลิงก์ในเมนูด้านซ้ายยังพาไปแต่ละหน้าได้ตามปกติ)
- **ตารางโต๊ะในหน้าหลัก** — หน้า `/shop/orders.html` แสดง **รายชื่อโต๊ะเป็นช่องสี่เหลี่ยมจัตุรัส** จัดกลุ่มตามโซน เรียงตามลำดับที่ตั้งไว้ · **ช่องที่ยังไม่มี QR** (ชื่อที่ QR ถูกปิดใช้งานไปแล้ว) กดแล้วออก QR ให้ทันที (ถามยืนยันก่อน) · **ช่องที่มี QR แล้ว** กดแล้ว **เปิดหน้าใหม่ `/shop/table.html?table=<id>`** ซึ่งแสดง **รูป QR + ปุ่มพิมพ์/ดาวน์โหลด/เปลี่ยนชื่อ/ย้ายโซน/ปิดใช้งาน QR** และ **บิลปัจจุบันของโต๊ะนั้น** (รายการอาหาร สถานะ ยอดรวม ลบรายการได้ พร้อมปุ่มเช็คบิลที่เปิดหน้าใบเสร็จให้พิมพ์ต่อ) — ช่องที่โต๊ะมีออเดอร์ค้างจะขึ้นจำนวนรายการ ยอดเงิน และจำนวนที่ยังรอทำ
- **โซนโต๊ะ (เพิ่มโซนเท่านั้น)** — ปุ่ม **“เพิ่มโซน”** ในหน้า `/shop/orders.html` เปิดป๊อปอัปสำหรับ **สร้าง/จัดโซน** เท่านั้น (ตั้งชื่อโซน เปลี่ยนชื่อ ลบ และจัดลำดับโซนด้วยปุ่มลูกศร) — ลบโซนแล้วโต๊ะไม่หาย แค่กลายเป็น “ไม่ระบุโซน” ส่วนการย้ายโต๊ะเข้า/ออกโซนทำได้ 2 ที่: ตอนเพิ่มโต๊ะใหม่ (เลือกโซนในป๊อปอัป) และที่ **หน้ารายละเอียดโต๊ะ** (`/shop/table.html`) ซึ่งมีตัวเลือก “โซน” ให้ย้ายทีหลังได้โดยไม่ต้องปิด QR
- **เพิ่มโต๊ะใหม่** — ปุ่ม **“＋ เพิ่มโต๊ะใหม่”** เปิดป๊อปอัปให้ **กรอกชื่อโต๊ะ + เลือกโซนที่จะจัดโต๊ะนี้เข้าไป** เท่านั้น แล้วระบบออก QR ให้ทันที (มีคำแนะนำชื่อโต๊ะที่เคยมีอยู่ รวมชื่อที่ QR ถูกปิดใช้งานไปแล้ว เพื่อพิมพ์ซ้ำได้โดยไม่ต้องจำ) — **ทุกครั้งที่จะออก QR มีกล่องยืนยันก่อน** กันเผลอกดโดน
- **เพิ่มโต๊ะ + ปิดใช้งาน QR อัตโนมัติ** — เพิ่มโต๊ะด้วยปุ่ม **“＋ เพิ่มโต๊ะใหม่”** ที่หน้า `/shop/orders.html` (กรอกชื่อ + เลือกโซน) แล้ว QR จะถูกออกให้ทันที และ **สวิตช์ “ปิดใช้งาน QR ของโต๊ะทันทีเมื่อเช็คบิล” ย้ายไปอยู่ที่หน้า “ตั้งค่าระบบ”** (`/shop/settings.html`) (กดเปลี่ยนแล้วมีกล่องยืนยันก่อนทุกครั้ง กันเผลอกดโดน) ถ้าเปิด เมื่อกดเช็คบิล QR ของโต๊ะนั้นจะ **ถูกปิดใช้งานทันที** (ต้องสร้าง QR ใหม่ก่อนให้ลูกค้าสั่งครั้งถัดไป) ถ้าปิด โต๊ะและ QR อยู่ต่อพร้อมเปิดบิลใหม่ให้อัตโนมัติ — **QR ที่ปิดใช้งานจะถูกยกเลิกถาวร** (โทเคนถูกบันทึกไว้ในตาราง `retired_table_tokens` และระบบจะไม่ออกโทเคนนั้นให้ใครอีก) แม้จะสร้างโต๊ะชื่อเดิมใหม่ ก็ได้ QR ใหม่เสมอ ของเก่าใช้ไม่ได้อีก — **ปิดใช้งานคือ “ไม่ลบ” โต๊ะและ QR จะถูกเก็บไว้ในประวัติ** (`tables.retired_at`) เพื่อเป็นหลักฐาน: ดูรูป QR เดิม, วันที่สร้าง/วันที่ปิดใช้งาน และยอดขายของโต๊ะนั้นได้ที่ **หน้า “ประวัติ” แท็บ “QR โต๊ะที่ปิดใช้งาน”** และยัง **ออก QR ชื่อเดิมใหม่ได้ทันที** เพราะ UNIQUE ของชื่อโต๊ะนับรุ่นด้วย (`shop_id, code, retire_seq`) — **บิลที่เช็คบิลแล้วจะไม่หายไปพร้อมโต๊ะ**: บิลเก็บชื่อโต๊ะไว้เองตั้งแต่เปิดบิล (`orders.table_code`) และ FK ของ `orders.table_id` เป็น `ON DELETE SET NULL` ดังนั้นกดเช็คบิลแล้วปิดใช้งาน QR ทันทีก็ยังเปิด **ใบเสร็จย้อนหลัง** และเห็นบิลใน **หน้าประวัติ** ได้ตามปกติ (บิลที่ยังเปิดอยู่แต่ยังไม่มีรายการจะถูกลบทิ้งตอนปิดใช้งานโต๊ะ เพราะเช็คบิลไม่ได้อีกแล้ว)
- **หน้าตั้งค่าระบบ** `/shop/settings.html` — รวมตัวเลือกการทำงานของระบบร้านไว้ที่เดียว (เข้าจากเมนูด้านซ้าย “ตั้งค่าระบบ”) ปัจจุบันมีสวิตช์ **“ปิดใช้งาน QR ของโต๊ะทันทีเมื่อเช็คบิล”** พร้อมป้ายบอกสถานะ (เปิดอยู่/ปิดอยู่) และคำอธิบายผลของทั้งสองโหมด — อ่านค่าจาก `/api/shop/me` และบันทึกผ่าน `PUT /api/shop/qr-auto-delete` (กดเปลี่ยนมีกล่องยืนยันก่อนทุกครั้ง กันเผลอกดโดน) — หน้าสั่งอาหารมีลิงก์มาที่หน้านี้ให้ด้วย
- **เลขที่บิล** — รันต่อร้าน (เริ่ม `#0001`) แสดงบนหน้าบิลของร้าน หน้าลูกค้า และบนป้ายที่พิมพ์ (ปุ่ม "พิมพ์ QR" ของแต่ละโต๊ะ เปิดหน้า `/shop/label.html?table=<id>`) — หน้าป้ายเป็น **หน้าจริงแบบเดียวกับใบเสร็จ**: มี **โลโก้ร้านอยู่บนสุดตรงกลาง** ตามด้วยชื่อร้าน **ชื่อโต๊ะ (บรรทัดเดียวเสมอ ไม่มีคำว่า "โต๊ะ" นำหน้า — ถ้าชื่อยาวระบบจะย่อขนาดตัวอักษรให้พอดีกระดาษอัตโนมัติ)** เลขที่บิล และ QR พร้อม **ปุ่มพิมพ์** และ **ตัวเลือกขนาดกระดาษ** (ม้วน 58/80mm, ค่าเริ่มต้น 80mm — ใช้ค่าร่วมกับใบเสร็จเพราะเป็นเครื่องพิมพ์เดียวกัน) พิมพ์อัตโนมัติเมื่อเปิดหน้า และแถบปุ่มจะไม่ติดไปกับกระดาษ
- **หน้าครัว** `/shop/kitchen.html` — รวมรายการอาหารของบิลที่เปิดอยู่ **พร้อมรูปอาหาร** และ **นาฬิกาจับเวลาต่อรายการ** (นับจากเวลาที่ลูกค้าสั่ง อัปเดตทุกวินาที เปลี่ยนสีตามความนาน: เขียว <5 นาที, เหลือง 5–15 นาที, แดง >15 นาที; รายการที่เสร็จแล้วจะหยุดเวลาไว้) **เรียงตามลำดับที่ลูกค้าสั่ง (คิวก่อน-หลัง)** — กดเริ่มทำแล้วตำแหน่งไม่ขยับ รายการใหม่ต่อท้ายคิว และรายการที่เสร็จแล้วจะจมไปล่างสุด ปุ่ม รอทำ มีตัวเลขแจ้งเตือนจำนวนรายการที่ยังไม่เริ่มทำ กรองตามสถานะ และสลับการจัดกลุ่มได้ด้วยปุ่ม: **ตามโต๊ะ** (แยกการ์ดต่อโต๊ะ/บิล) หรือ **ตามเมนู** (เมนูเดียวกันจากต่างโต๊ะรวมการ์ดเดียว) พร้อมปุ่ม **เริ่มทำ** และ **เคลียร์อาหาร**
- **อัปเดตเรียลไทม์ (SSE)** — ครัว · แคชเชียร์ · หน้าสั่งอาหาร · หน้ารายละเอียดโต๊ะ เปิดคอนเนกชันค้างไว้ที่ `GET /api/shop/events` และ **ข้อมูลจะขึ้นทันทีที่ร้านมีเหตุการณ์** โดยไม่ต้องรีเฟรช (วัดจริง ~0.4 วินาที) รวมถึง **ตัวเลขมาร์คบนปุ่ม "รอทำ"** ที่อัปเดตเอง · เหตุการณ์ที่ผลัก: `order_new` (ลูกค้าสั่ง/แคชเชียร์เพิ่มอาหาร) · `item_status` (ครัว/แคชเชียร์เปลี่ยนสถานะหรือยกเลิก) · `bill_changed` (ลบรายการ) · `checkout` (เช็คบิล) · `tables_changed` (เพิ่ม/เปลี่ยนชื่อ/ปิดใช้งานโต๊ะ · รายชื่อโต๊ะ · โซน) — ฝั่งเซิร์ฟเวอร์คือ `src/lib/realtime.js` (แยกกลุ่มตามร้าน เห็นเฉพาะเหตุการณ์ของร้านตัวเอง · heartbeat ทุก 25 วิ · ตั้ง `X-Accel-Buffering: no` ให้ Nginx ส่งถึงทันทีโดยไม่ต้องแก้ config) · ฝั่งเบราว์เซอร์คือ `public/js/realtime.js` (`shopLive({ onEvent })` ต่อใหม่เองอัตโนมัติเมื่อหลุด + ดึงข้อมูลใหม่เมื่อกลับมาเปิดแท็บ) — **ยังมีตัวจับเวลาเดิมเป็นตัวสำรอง** (ครัว/แคชเชียร์ 30 วิ · หน้าสั่งอาหาร 30 วิ) เผื่อกรณีเน็ตหลุดหรือ proxy ตัดการเชื่อมต่อ
  - หมายเหตุ: ป้ายตัวเลขบนปุ่ม "รอทำ" นับเป็น **จำนวนจาน** (ผลรวม quantity) ให้ตรงกับส่วนอื่นของระบบ
- **เส้นทางแสดงผล ครัว / แคชเชียร์** — ตั้งได้ที่หน้าจัดการเมนู ตอนสร้างหรือแก้ **หมวดหมู่** (เลือก "ส่งเข้า ครัว" หรือ "ส่งเข้า แคชเชียร์") เมนูในหมวดนั้นจะไปแสดงที่จุดที่เลือกเท่านั้น
- **หน้าแคชเชียร์** `/shop/cashier.html` — หน้าจอเดียวกับครัว (รูปอาหาร, นาฬิกาจับเวลา, กรอง/จัดกลุ่ม, ยกเลิกรายการ) แต่แสดงเฉพาะรายการของหมวดที่ตั้งเส้นทางไว้ที่แคชเชียร์ และใช้ถ้อยคำของแคชเชียร์ (ยังไม่จัด / กำลังจัด / จัดเสร็จ) มีปุ่มสลับไป-กลับระหว่างครัวกับแคชเชียร์
- **แคชเชียร์ (ในหน้าบิลที่เปิดอยู่ `/shop/orders.html`)** — **เพิ่มอาหาร** เข้าบิลได้ (เลือกเมนู + ตัวเลือก + จำนวน, คิดราคาที่เซิร์ฟเวอร์) และ **ลบรายการ** ออกจากบิลได้ พร้อมเห็น **สถานะของทุกรายการ** (รอทำ/กำลังทำ/เสร็จแล้ว/ยกเลิก) และ **นาฬิกาจับเวลาต่อรายการ** (นับจากเวลาที่ลูกค้าสั่ง) — และ **เช็คบิลไม่ได้ถ้ายังมีรายการไม่เคลียร์** (รอทำ/กำลังทำ) ไม่ว่าจะเป็นรายการของครัวหรือแคชเชียร์
- **ปุ่มเช็คบิลในบล็อกโต๊ะ** — กดแล้วเปิดหน้าต่างตรวจรายการทั้งหมดของบิลนั้น (รายการ/จำนวน/สถานะ/ยอดรวม) กด "ยืนยันเช็คบิล" จึงปิดบิล + เปิดบิลใหม่ให้โต๊ะเดิม แล้วเปิด **หน้าใบเสร็จสำหรับพิมพ์** `/shop/receipt.html?order=<id>` (โลโก้ QPage กลางด้านบน, ชื่อร้าน, โต๊ะ, เลขที่บิล, วันที่, ตารางรายการ จำนวน/ราคาต่อหน่วย/รวม และยอดรวมทั้งสิ้น — พิมพ์อัตโนมัติเมื่อเปิดหน้า) เลือกขนาดกระดาษได้ 3 แบบ: ม้วน 58mm / ม้วน 80mm (ค่าเริ่มต้น) / A4 โดยตั้งขนาด @page เป็น mm + auto สำหรับกระดาษม้วนยาว และจำค่าที่เลือกไว้ในเครื่อง
- **ลบโต๊ะ/QR** ได้เฉพาะเมื่อบิลว่าง — ถ้าโต๊ะยังมีบิลที่ไม่ได้เช็คบิล (มีรายการค้าง) จะลบไม่ได้จนกว่าจะกดเช็คบิลก่อน
- **หน้าประวัติ** `/shop/history.html` — มี 2 แท็บ: **ประวัติบิล** และ **QR โต๊ะที่ปิดใช้งาน**
  - *ประวัติบิล* — ดูย้อนหลังเป็นบิล ๆ ต่อโต๊ะ (กดที่บิลเพื่อกางดูรายการ/ตัวเลือก/ยอด และเวลาเปิด-ปิดบิล) **กรองตามโต๊ะ** ได้ (รวมโต๊ะที่ปิดใช้งานแล้ว ซึ่งจะกำกับว่า "(ปิดใช้งาน)") กำหนดจำนวนบิลล่าสุด (50/100/200) และ **ออกรายการเป็น CSV** ได้ และในแต่ละบิลที่กางออกมีปุ่ม **"🖨 ขอใบเสร็จ (พิมพ์ใหม่)"** เปิดหน้าใบเสร็จของบิลนั้นในแท็บใหม่เพื่อพิมพ์ซ้ำได้
  - *QR โต๊ะที่ปิดใช้งาน* — การ์ดของทุกโต๊ะที่ปิดใช้งานแล้ว พร้อม **รูป QR เดิม** (กดดู/ดาวน์โหลดเป็นหลักฐานได้), โซน, **วันที่สร้าง QR**, **วันที่ปิดใช้งาน**, จำนวนบิลที่ปิดแล้วและยอดขายรวมของโต๊ะนั้น, ปุ่ม **"ดูบิลของโต๊ะนี้"** (สลับไปแท็บประวัติบิลพร้อมกรองโต๊ะนั้นให้) และ **ออกรายการเป็น CSV**
- **บิลถูกเช็คบิล → หน้าลูกค้าที่เปิดค้างออกจากโหมดสั่งอัตโนมัติ** — หน้าสั่งอาหารของลูกค้าผูกกับเลขที่บิลตอนเปิด ถ้าร้านกดเช็คบิล (ระบบตรวจทุก 8 วินาที) หน้าจะพาไป **หน้าดูร้าน** `/s/<code>?bill_closed=1` ซึ่งดูเมนูได้อย่างเดียว สั่งไม่ได้ พร้อมแจ้งว่าให้สแกน QR ที่โต๊ะใหม่ และฝั่งเซิร์ฟเวอร์ก็ปฏิเสธการส่งออเดอร์ที่อ้างบิลเก่า (409) กันของหลุดเข้าบิลใหม่
- **สถานะรายจาน** — หน้าลูกค้าแสดงสถานะของแต่ละรายการ (รอทำ/กำลังทำ/เสร็จแล้ว) และ **ยกเลิกรายการได้เฉพาะที่ครัวยังไม่กดเริ่มทำ** (ถ้าเริ่มทำ/เสร็จแล้วจะยกเลิกไม่ได้)
- **ตั้งค่าการแจ้งเตือน** `/shop/notify.html` — ตั้ง **กลุ่มแจ้งเตือน** ผ่าน **Telegram (Bot API)** ได้ **มากกว่า 1 กลุ่ม** แต่ละกลุ่มเลือกเองว่าจะรับเหตุการณ์อะไรบ้าง: มีออเดอร์ใหม่ / อาหารทำเสร็จ / ยกเลิกรายการ / เช็คบิล (ปิดบิล) — ข้อความ **เช็คบิล** แนบ **รายการอาหารทั้งหมด** ของบิลนั้น (ชื่อเมนู + ตัวเลือก + จำนวน + ราคา, รายการที่ถูกยกเลิกกำกับ "(ยกเลิก)" และไม่คิดเงิน) พร้อม **วันและเวลาที่เช็คบิล** (เวลาไทย) — ตั้งชื่อกลุ่มและแยกปลายทางได้ (เช่น กลุ่มครัวรับออเดอร์ใหม่ กลุ่มผู้จัดการรับเฉพาะเช็คบิล) ระบุ Topic ID ได้เมื่อส่งในหัวข้อของกลุ่ม เปิด-ปิดแต่ละกลุ่มด้วยสวิตช์ จำกัด 20 กลุ่ม/ร้าน มีปุ่ม **ทดสอบส่ง** ที่บอกสาเหตุจาก Telegram ถ้าไม่สำเร็จ และเก็บผลการส่งล่าสุดไว้บนการ์ด การส่งเป็นแบบ best-effort — ล้มเหลวแล้วไม่กระทบการสั่งอาหารหรือเช็คบิล (ตั้ง env `TELEGRAM_API_BASE` เพื่อเปลี่ยนปลายทาง API ได้ ใช้ตอนทดสอบ) — *ระบบเลือกใช้ Telegram อย่างเดียว เพราะ LINE ไม่มีช่องทางส่งเข้าบัญชี LINE ส่วนตัวโดยตรงแล้ว (LINE Notify ปิดบริการ 31 มี.ค. 2025) และต้องมี Official Account*
- **ยกเลิกจากครัว** — ครัวกดปุ่ม "ยกเลิก" ที่รายการได้ (ตอนยังไม่เสร็จ) โดยต้อง **เลือกสาเหตุ: วัตถุดิบหมด หรือ อื่น ๆ (พิมพ์ระบุ)** — รายการที่ยกเลิกจะ **ไม่ถูกคิดเงิน** และลูกค้าเห็นสถานะ "ยกเลิก" พร้อมสาเหตุนั้น (การยกเลิกไม่ลบข้อมูล เก็บไว้เป็นประวัติ)
- **นับ "รายการ" เป็นจำนวนจาน** (ผลรวม quantity) ทุกที่ที่สรุปยอดบิล — หน้าบิลที่เปิดอยู่ ประวัติออเดอร์ ใบเสร็จ และข้อความแจ้งเตือน ใช้ตัวเลขเดียวกัน ส่วนจำนวน "เมนู" ที่ต่างกันจะแสดงแยกเป็นคำว่า "เมนู" เพื่อไม่ให้สับสน (เช่น ใบเสร็จ: "9 รายการ · 7 เมนู")
- ราคาและตัวเลือกถูก **คำนวณ/ตรวจที่เซิร์ฟเวอร์เสมอ** (ไม่เชื่อค่าจาก client) และบันทึกชื่อ/ราคาเมนู ณ ตอนสั่งไว้ในบิล
- QR สร้างในเครื่องด้วยไลบรารี `qrcode` (ทำงานออฟไลน์ได้)

API: `GET/POST/PUT/DELETE /api/shop/tables`, `GET /api/shop/tables/:id/qr` (PNG), `GET /api/shop/orders/open`, `POST /api/shop/tables/:id/checkout`, `GET /api/shop/orders/history`, `GET/POST/PUT/DELETE /api/shop/notify-groups`, `POST /api/shop/notify-test`, `GET /api/public/order/:token`, `POST /api/public/order/:token/items`

API หลัก: `POST /api/shop/purchase`, `GET/POST/PUT /api/shop(/me)`, CRUD `/api/shop/categories|menus|option-groups|option-items`, `PUT /api/shop/menus/:id/groups`, `POST /api/shop/upload`, และ `GET /api/public/shops/:code`

## 🧪 โหมดทดสอบ (`DEV_MODE=true`)

โหมด dev ยังไม่ส่ง SMS/อีเมลจริง แต่แสดงที่ console ของเซิร์ฟเวอร์และบนหน้าเว็บ:
- 📱 รหัส OTP ทาง SMS → แสดงในหน้าสมัครสมาชิก (กล่อง "โหมดทดสอบ")
- 📧 รหัสยืนยันอีเมล → แสดงในหน้าสมัครสมาชิกเมื่อยังไม่ได้ตั้งค่า SMTP
- 📧 ลิงก์ยืนยันอีเมล (บัญชีเดิม) → แสดงบนหน้าบัญชีหลังกด "ส่งลิงก์ยืนยันอีเมล"

## 🔌 วิธีต่อ service จริง (production)

1. **SMS ส่ง OTP จริง** — ตั้งค่า `TWILIO_*` หรือ `TBS_*` ใน `.env` (หรือตั้งผ่านหน้า `/admin/otp.html`)
2. **อีเมลจริง (SMTP)** — ตั้งค่า `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`
3. **Google reCAPTCHA** — สร้าง key ที่ https://www.google.com/recaptcha/admin แล้วใส่ `RECAPTCHA_SITE_KEY`, `RECAPTCHA_SECRET_KEY`
4. **Google Login (OAuth)** — สร้าง OAuth Client ID ที่ https://console.cloud.google.com/apis/credentials
   - Authorized redirect URI = `http://localhost:3000/api/auth/google/callback` (หรือโดเมนจริง)
   - ใส่ `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`
5. **ปิดโหมด dev** — ตั้ง `DEV_MODE=false`

`js/shop-ui.js` = ตัวช่วยที่ใช้ร่วมกันทุกหน้าฝั่งร้านและหน้าลูกค้า (`esc`, `money`, `billNoFmt`, `dt`, `platesOf`, `openBlankTab`, `gotoReceipt` + **กล่องโต้ตอบแบบมี UI ของเว็บ**) โหลดด้วย `<script src="/js/shop-ui.js">` ในแต่ละหน้า ไม่ต้องมี build step — หน้าที่ต้องการตัวเลขแบบไม่มีสัญลักษณ์ ฿ (menus.html, purchase.html) ใช้ `moneyNum` ของตัวเอง ส่วนตัวช่วยที่ผูกกับหน้าจอ (เช่น `api`, `toast`) ยังอยู่ในหน้าแต่ละหน้าเพราะรายละเอียดต่างกัน

**กล่องโต้ตอบของเว็บ (ไม่ใช้กล่องของเบราว์เซอร์)** — `uiConfirm({ title, message, okText, danger })` → `true/false`, `uiPrompt({ title, label, value })` → ข้อความ/`null`, `uiAlert({ title, message })` — หน้าตาเป็นสไตล์เดียวกับป๊อปอัปของเว็บ (การ์ดขาว มุมโค้ง ฉากมืด) ปิดได้ด้วยปุ่ม/ESC/คลิกฉากมืด และโฟกัสช่องกรอกอัตโนมัติ (Enter = ยืนยัน) ใช้แทน `confirm()`/`prompt()`/`alert()` ทุกจุดในหน้าฝั่งร้าน · หน้าลูกค้า · หน้าบัญชี และหน้าจัดการแพ็กเกจของหลังบ้าน (สไตล์ถูกฉีดเข้าไปพร้อมกล่อง จึงใช้ได้ทุกหน้าแม้หน้านั้นไม่โหลด `shop.css`)

**สีป๊อปอัปแยกตามธีม** — ป๊อปอัปทุกตัว (ป๊อปอัปของเว็บและกล่องโต้ตอบข้างบน) ใช้ตัวแปรกลาง 3 ตัวจาก `style.css`: `--modal-bg` (พื้นการ์ด), `--modal-border` (เส้นขอบ), `--overlay` (ฉากมืด) — โหมดสว่างเป็นการ์ดขาว/ฉากมืดเดิม ส่วน **โหมดมืดการ์ดจะสว่างกว่าการ์ดบนหน้าปกติ (`--surface`)** และฉากมืดเข้มขึ้น เพื่อให้ป๊อปอัปเด่นออกจากพื้นหลังเสมอ (แก้ที่ตัวแปรที่เดียว มีผลทุกป๊อปอัป รวมทั้งหลังบ้าน)

`js/brand-icons.js` = ไอคอนแบรนด์ **Facebook / LINE** ที่ใช้ร่วมกันหน้าเว็บหลักและหน้าตั้งค่าหลังบ้าน (`BRAND_ICON.facebookF`, `BRAND_ICON.line`) — path มาจากชุดไอคอนแบรนด์มาตรฐาน **ไม่ได้วาดขึ้นเอง** จึงได้ตัวอักษรจริงทั้งสองแบรนด์ (Facebook f เดี่ยวจาก Font Awesome Free 6 / LINE จาก simple-icons) · ไอคอนใช้ `fill="currentColor"` เปลี่ยนสีด้วย CSS ที่ปุ่ม (`public/css/style.css` → `.social-btn`)

## 🖥️ โปรแกรม Windows (`desktop/`) — หน้าจอร้าน + พิมพ์เงียบ + ตัวช่วยพิมพ์ให้แท็บเล็ต

โปรแกรมแยกต่างหากสำหรับคอมที่ร้าน (Electron) ใช้โค้ดเว็บชุดเดิมเป็นแกน — **ไม่ต้องแก้หน้าเว็บเลย**
ตัวโปรแกรมเปิดหน้าจอระบบร้านในหน้าต่างโปรแกรม (ไม่มีแถบเบราว์เซอร์) แล้ว **ดัก `window.print()` ของหน้าเว็บ**
เพื่อพิมพ์ใบสั่งครัว/ใบเสร็จ/ป้าย QR แบบไม่ขึ้นกล่องยืนยัน (หน้าเว็บทั้ง 3 หน้าสั่งพิมพ์เองที่จุดเดียว จึงดักที่จุดเดียวพอ)

**ไฟล์ในโฟลเดอร์ `desktop/`**
- `main.js` — หน้าต่างหลัก + เมนูไทย + ดักการพิมพ์ + หน้าต่างตั้งค่า + โหมดทดสอบตัวเอง (`--selftest`)
- `preload.js` / `settings-preload.js` — สะพานเชื่อมหน้าเว็บกับโปรแกรม (เปิดให้แค่สั่งพิมพ์/อ่านค่าตั้ง)
- `lib/settings.js` — ค่าตั้งใน `%APPDATA%\QPage Shop\settings.json` (+ รหัสเครื่องสำหรับกันพิมพ์ซ้ำ)
- `lib/print.js` — สร้างตัวเลือกการพิมพ์ตามชนิดเอกสาร (เครื่องพิมพ์ + ขนาดกระดาษ)
- `lib/agent.js` — ตัวช่วยพิมพ์: ลงทะเบียน/heartbeat 30 วิ + ฟัง SSE + เปิดงานในหน้าต่างซ่อนแล้วพิมพ์ + รายงานผล
- `settings.html` + `settings.js` — หน้าตั้งค่าในโปรแกรม (เครื่องพิมพ์/ขนาดกระดาษแยก 4 ชนิด, สวิตช์, ประวัติการพิมพ์, ปุ่มพิมพ์ทดสอบ)
- `test-ticket.html` — ใบสั่งครัวตัวอย่างสำหรับ "พิมพ์ทดสอบ"
- `build/make-icon.js` — สร้างไอคอนแอป (`build/icon.ico`) จากโลโก้เว็บ

**ติดตั้ง/ใช้งาน**
1. `cd desktop && npm install` — ถ้า npm บล็อกสคริปต์ติดตั้งของ Electron (npm รุ่นใหม่กันไว้) ให้สั่งดาวน์โหลดไบนารีเอง: `node node_modules/electron/install.js`
2. `npm run dist` → ได้ไฟล์ติดตั้ง `dist/QPage Shop Setup 1.0.0.exe` (ติดตั้งระดับผู้ใช้ ไม่ต้องสิทธิ์ผู้ดูแล) และแบบพกพา `dist/QPage Shop 1.0.0.exe` — **ไม่ต้องขึ้นสโตร์ เอาไฟล์ไปติดตั้งได้เลย** (Windows จะเตือน "ไม่รู้จักผู้เผยแพร่" ครั้งแรกถ้าไม่ได้ซื้อใบรับรอง code signing)
3. เปิดโปรแกรม → เข้าสู่ระบบด้วยบัญชีเจ้าของร้าน (คุกกี้เก็บถาวร ล็อกอินครั้งเดียวอยู่ได้ตามอายุ session)
4. เมนู **ไฟล์ → ตั้งค่าเครื่องพิมพ์…** เลือกเครื่องพิมพ์ + ขนาดกระดาษ **แยกตามชนิดเอกสาร** (ใบสั่งครัว / ใบเสร็จ / ป้าย QR / อื่น ๆ) แล้วกด **พิมพ์ทดสอบ**

**⚠️ เรื่องขนาดกระดาษ (ทดสอบบน Windows จริงแล้ว)**
Chromium **ไม่รับขนาดกระดาษที่กำหนดเอง** (เช่น 80mm × 297mm จะได้ error `Printing failed`) เพราะ Windows ยอมรับเฉพาะขนาดที่ไดรเวอร์เครื่องพิมพ์ประกาศไว้
→ วิธีที่ถูกต้องสำหรับม้วน 58/80mm คือ **ตั้งขนาดกระดาษในไดรเวอร์ของเครื่องพิมพ์ครั้งเดียว** (Printer properties → Preferences → Paper size) แล้วเลือก **"ตามที่ตั้งไว้ในเครื่องพิมพ์"** ในโปรแกรม ซึ่งเป็นค่าเริ่มต้นอยู่แล้ว · ส่วน A4/Letter/Legal เลือกได้ตรง ๆ

**หน้าจอที่โปรแกรมวาดเอง (ไม่ใช่หน้าเว็บ)** — ย้ายทีละหน้า เริ่มจากหน้าที่ใช้บ่อยที่สุด
- `desktop/app/kitchen.html` + `kitchen.js` = **หน้าจอครัวของโปรแกรมเอง** (การ์ดแยกตามโต๊ะ/บิล · ปุ่มเริ่มทำ/เคลียร์อาหาร/ยกเลิกพร้อมสาเหตุ · ตัวกรองสถานะ · จัดกลุ่มตามเมนู · นาฬิกาจับเวลาต่อรายการและต่อโต๊ะ · สรุปจำนวนจาน · ปุ่ม "เริ่มทำทั้งโต๊ะ" ที่พิมพ์ใบสั่งครัวให้ด้วย) — กด "เริ่มทำ" รายรายการ = เปลี่ยนสถานะ **และพิมพ์ใบสั่งครัวทันที** (เหมือนหน้าเว็บ: เส้นทางเดียวกับปุ่มเริ่มทั้งโต๊ะ จึงได้รอบพิมพ์ทุกครั้ง)
- **หน้าจอแคชเชียร์ใช้ไฟล์เดียวกันกับครัวเป๊ะ ๆ** (`app/kitchen.html?station=cashier`) ต่างกันแค่กรองเฉพาะหมวดที่ตั้งเส้นทางไว้ที่แคชเชียร์ (เครื่องดื่ม/ของว่าง) และคำเรียก (เริ่มจัด/จัดเสร็จ/ยังไม่จัด) — เหมือนหน้าเว็บที่ `/shop/cashier.html` ใช้ไฟล์เดียวกับ `/shop/kitchen.html` · งานเก็บเงิน/พิมพ์ใบเสร็จอยู่ในหน้าจอ "สั่งอาหาร" ตามเดิม
- `desktop/app/history.html` + `history.js` = **หน้าจอ "ประวัติ" ของโปรแกรมเอง** — สามแท็บในจอเดียว (ตรงกับหน้าเว็บที่มีปุ่มเชื่อมกัน)
  - **ประวัติบิล**: บิลที่ปิดแล้ว (กรองตามโต๊ะ/จำนวนบิลล่าสุด) · กางดูรายการในบิลพร้อมตัวเลือกและรายการที่ถูกยกเลิก (ขีดฆ่า + บอกสาเหตุ + ไม่คิดเงิน) · **พิมพ์ใบเสร็จซ้ำ** · ออกรายการ CSV
  - **QR โต๊ะที่ปิดใช้งาน**: การ์ดของโต๊ะที่เลิกใช้แล้ว พร้อมรูป QR จริง (main โหลด PNG มาให้เป็น data URL เพราะหน้าจอไฟล์ในเครื่องโหลดรูปจากเซิร์ฟเวอร์ตรง ๆ ไม่ได้) · ยอดขายของโต๊ะนั้น · **ดาวน์โหลด QR** · ดูบิลของโต๊ะนี้
  - **ประวัติสั่งครัว**: รอบการพิมพ์ใบสั่งครัวทั้งหมด (ใหม่สุดก่อน) · บอกจุดที่พิมพ์ (ครัว/แคชเชียร์) · เวลาพิมพ์ถึงระดับวินาที · กางดูสำเนารายการที่พิมพ์ไปจริงในรอบนั้น · **พิมพ์รอบนี้ซ้ำ** · ออกรายการ CSV — เมนู "ประวัติสั่งครัว" ในแถบซ้ายเปิดหน้าจอนี้ที่แท็บนี้ให้ทันที
  - **ออกรายการ/ดาวน์โหลด** จะบันทึกลงโฟลเดอร์ **Downloads** ของเครื่องแล้วแจ้งพาธ (กดที่ข้อความแจ้งเพื่อเปิดโฟลเดอร์) — ไม่มีกล่องให้เลือกพาธ เพราะพนักงานหน้าร้านกดพลาดง่าย
  - อัปเดตเองเมื่อมีการเช็คบิล/ปิดใช้งาน QR ระหว่างเปิดหน้านี้อยู่ (ผ่าน SSE ชุดเดียวกับครัว)
- `desktop/app/orders.html` + `orders.js` = **หน้าจอ "สั่งอาหาร" ของโปรแกรมเอง** — ผังโต๊ะแยกตามโซน (เลขโต๊ะ · เลขบิล · จำนวนจาน · ยอดเงิน · โต๊ะว่าง) · แผงบิลด้านขวา (รายการ+ตัวเลือก+สถานะครัว · ลบรายการ · ยอดรวม) · เพิ่มอาหาร (ค้นหาเมนู · กลุ่มตัวเลือกบังคับพร้อม ⭐ ค่าเริ่มต้นของร้าน · ราคาเสริม · จำนวน) · **เช็คบิลแล้วพิมพ์ใบเสร็จเงียบ** · เพิ่มโต๊ะ/เพิ่มโซนได้จากหน้านี้
  - ⚠️ กับดักที่เจอตอนทำ: `/api/shop/tables` ส่งบิลมา **โดยไม่มีรายการอาหาร** — ต้องใช้บิลจาก `/api/shop/orders/open` (ที่มี `items`) ทับเสมอ และบิลว่างที่เพิ่งเปิดใหม่ (หลังเช็คบิล) ไม่นับเป็น "มีบิล"
  - ⚠️ กับดักที่สอง: **ผังโต๊ะต้องสร้างจาก `/api/shop/table-names`** (รายชื่อโต๊ะ + โซนทั้งหมดที่ร้านตั้งค่าไว้) ไม่ใช่ `/api/shop/tables` ซึ่งให้เฉพาะโต๊ะที่ **ออก QR แล้ว** — ถ้าใช้ `/tables` ผังจะว่างเปล่าทั้งที่ในระบบมีโต๊ะอยู่ · ชื่อที่ตั้งไว้แต่ยังไม่ออก QR จะแสดงเป็นช่อง "ยังไม่ออก QR · กดเพื่อออก QR" (กดแล้วออก QR ให้ทันที) แล้วค่อยผูกข้อมูล QR/บิลเข้ากับชื่อนั้นด้วยฟิลด์ `has_qr`/`table_id` ที่ `/table-names` ส่งมาให้ (เซิร์ฟเวอร์จับคู่จาก `code` = `name` เอง)
- หน้าจอนี้เป็นไฟล์ในเครื่อง (file://) จึง **ไม่เรียก API เอง** — ส่งคำสั่งผ่าน IPC ให้ `main` ซึ่งถือ session ของร้านอยู่แล้วเป็นคนเรียก API ให้ (ดู `desktop/lib/api.js` และ `desktop/preload.js` → `qpageKitchen`)
- **อัปเดตสด**: `main` เปิดสาย SSE (`/api/shop/events`) ไว้ แล้วส่งอีเวนต์เข้าหน้าจอ → หน้าจอดึงข้อมูลใหม่ทันทีเมื่อมีออเดอร์ใหม่/สถานะเปลี่ยน (มีโพลทุก 30 วินาทีเป็นตัวสำรอง)
- **พิมพ์ใบสั่งครัวจากหน้าจอโปรแกรม**: `POST /api/shop/order-items/start` ตอบกลับพร้อม `rounds` (รหัสรอบพิมพ์ + ลิงก์) → โปรแกรมเปิด `/shop/ticket.html?round=…` ในหน้าต่างซ่อนแล้วดักพิมพ์เงียบ ผลลัพธ์จึงเหมือนพิมพ์จากหน้าเว็บเป๊ะ
- **หน้าจอ "จัดการร้าน" ทั้งชุดเป็นของโปรแกรมเองแล้ว** (สไตล์ร่วมกันที่ `desktop/app/admin.css`)
  - `app/menu.html` + `menu.js` = **จัดการเมนู**: หมวดหมู่ (+ หมวดย่อย) พร้อมสลับเส้นทางครัว/แคชเชียร์ · เปลี่ยนชื่อ/ลบหมวด · เมนูในแต่ละหมวด · กลุ่มตัวเลือกและตัวเลือกในกลุ่ม (บังคับเลือก/หลายอย่าง/บวกเพิ่ม/⭐ ค่าเริ่มต้น) · ผูกกลุ่มตัวเลือกกับเมนูได้จากหน้าต่างแก้ไขเมนู
  - `app/menus.html` + `menus.js` = **เมนูทั้งหมด**: ค้นหา · กรองตามหมวด/สถานะ · เปิด-ปิดการขายด้วยสวิตช์ในแถว · เพิ่ม/แก้ไข/ลบเมนู (ชื่อ ราคา รายละเอียด หมวด รูป)

  - รูปที่เก็บอยู่บนเซิร์ฟเวอร์แสดงในหน้าจอได้ด้วยการให้ main ดึงมาเป็น data URL (`shop:image-data`) เพราะหน้าจอเป็นไฟล์ในเครื่อง (ไม่มีคุกกี้)

  - โลโก้ QPage ตรงกลางด้านบน + คำว่า "เข้าสู่ระบบ" + ช่องอีเมล/รหัสผ่าน + **ปุ่มเข้าสู่ระบบปุ่มเดียว (ไม่มีปุ่มสมัครสมาชิก)**
  - **เงื่อนไขการใช้โปรแกรม**: ต้องล็อกอินได้ + มีร้านค้า + มีแพ็กเกจที่ยังไม่หมดอายุ (ซื้อไว้ หรือของขวัญจากแอดมิน) — เซิร์ฟเวอร์เป็นคนตัดสินผ่านฟิลด์ `entitled` / `entitlement_end` ใน `/api/shop/me`
  - ถ้าไม่มีแพ็กเกจ/หมดอายุ: เข้าใช้โปรแกรมไม่ได้ + ซ่อนแถบเมนูทั้งแถบ · แสดงกล่องอธิบายพร้อมปุ่ม **ซื้อ/ต่ออายุแพ็กเกจ** (เปิดในเบราว์เซอร์ของเครื่อง) · **ตรวจสอบสิทธิ์อีกครั้ง** · **ออกจากระบบ** — ข้อมูลร้าน/เมนู/ประวัติลูกค้า **ไม่ถูกลบ** แค่เข้าใช้ไม่ได้จนกว่าจะมีแพ็กเกจ
  - ปุ่ม "ตรวจสอบสิทธิ์อีกครั้ง" ใช้หลังซื้อแพ็กเกจเสร็จ เพื่อเข้าโปรแกรมต่อได้ทันทีโดยไม่ต้องปิดโปรแกรม
- หน้าที่เหลือที่ยังโหลดหน้าเว็บมาแสดง: ไม่มี (ย้ายครบทุกหน้าในแถบซ้ายแล้ว) — เพิ่มหน้าจอใหม่ได้โดยใส่รายการในตาราง `NATIVE_PAGES` ที่ `desktop/main.js`
  - เส้นทางที่อยู่ในตาราง `NATIVE_PAGES` จะถูกสลับเป็นหน้าจอของโปรแกรม **ทุกทาง** ไม่ว่าจะกดจากแถบซ้าย หรือหน้าเว็บพาไปเอง (เช่น ล็อกอินเสร็จแล้วเว็บเด้งไป `/shop/kitchen.html` → โปรแกรมเปิดหน้าจอครัวของตัวเองทันที)
- ⚠️ ตอนทดสอบการพิมพ์ **ห้ามตั้งเครื่องพิมพ์เป็น "Microsoft Print to PDF"** — Windows จะเด้งหน้าต่างบันทึก/เปิด PDF เต็มจอ ใช้ "AnyDesk Printer" (เครื่องพิมพ์เสมือนที่พิมพ์เงียบ) หรือเครื่องพิมพ์ความร้อนจริงแทน

**ตัวช่วยพิมพ์ให้มือถือ/แท็บเล็ต** (เบราว์เซอร์มือถือพิมพ์เงียบเองไม่ได้ — ข้อจำกัดของทุกเบราว์เซอร์)
1. พนักงานกด "เริ่มทำ" บนแท็บเล็ต → เซิร์ฟเวอร์บันทึกรอบพิมพ์ (ประวัติสั่งครัว) **+ เข้าคิวงานพิมพ์** ถ้ามีเครื่องที่รับงานได้
2. โปรแกรมบนคอม (เปิดค้างไว้ + ล็อกอินแล้ว) รับงานผ่าน SSE แล้วเปิดหน้านั้นใน **หน้าต่างซ่อน** → พิมพ์เงียบ → รายงานผลกลับ
3. **กันพิมพ์ซ้ำ**: โปรแกรมแนบ header `X-QPage-Device` ทุกคำขอ → คำสั่งที่มาจากเครื่องที่พิมพ์เองจะไม่เข้าคิว (พิมพ์ทันทีในเครื่อง)
4. **ไม่สร้างงานค้าง**: ถ้าไม่มีตัวช่วยพิมพ์ออนไลน์ (heartbeat ภายใน 2 นาที) หรือไม่ได้เปิดรับชนิดนั้น → ไม่เข้าคิวเลย
5. ฝั่งเซิร์ฟเวอร์: ตาราง `print_agents` + `print_jobs` (เก็บ 30 วัน) และ API `POST /api/shop/print-agent` · `GET /api/shop/print-jobs` · `POST /api/shop/print-jobs/:id/status` (ทุกเส้นทางตรวจสิทธิ์เฉพาะร้านตัวเอง)

**ตรวจสอบ/แก้ปัญหา**
- ทดสอบตัวเอง: `cd desktop && npm run selftest -- --print-to="ชื่อเครื่องพิมพ์"` (ผลเขียนไว้ที่ `%APPDATA%\QPage Shop\selftest-result.json` ด้วย เพราะแอป GUI ไม่คายข้อความออกคอนโซล)
- พิมพ์ไม่ออก: ดู **ประวัติการพิมพ์ล่าสุดในเครื่องนี้** ในหน้าตั้งค่า (บอกเหตุผลที่ล้มเหลว) · ตรวจว่าเลือกเครื่องพิมพ์ถูก · ตรวจขนาดกระดาษในไดรเวอร์ · ตรวจว่าเครื่องพิมพ์ออนไลน์
- แท็บเล็ตสั่งแล้วไม่พิมพ์: ตรวจว่าโปรแกรมเปิดอยู่ **และล็อกอินแล้ว** และสวิตช์ "รับงานพิมพ์ …" ของชนิดนั้นเปิดอยู่ (หน้าตั้งค่าแสดงสถานะล็อกอิน + สถานะตัวช่วยพิมพ์)
- **กล่อง "A JavaScript error occurred in the main process — Cannot convert argument to a ByteString"**: เกิดเมื่อ **"ที่อยู่เซิร์ฟเวอร์" ในโปรแกรมตั้งไม่ถูกต้อง** แล้วคำขอไปโดนบริการอื่นในเครื่องตอบกลับ พร้อม header (`Date`) ที่จัดรูปแบบเป็นภาษาไทย ซึ่ง HTTP header ส่งไม่ได้ (รับเฉพาะ Latin-1) → Electron โยน error แล้วโปรแกรมล้มทั้งตัว (เจอจริงจากหน้างาน) ตอนนี้โปรแกรม **ไม่ล้มแล้ว** — เขียนสาเหตุลง `%APPDATA%\QPage Shop\startup.log` (บรรทัด `⚠️ เซิร์ฟเวอร์ตอบ header ที่มีอักษรพิเศษ`) และตัด header ที่ส่งไม่ได้ทิ้ง · วิธีแก้: เปิด **ไฟล์ → ตั้งค่าเครื่องพิมพ์…** แล้วตั้งที่อยู่เซิร์ฟเวอร์ให้ถูกต้อง (ปกติ `https://qpage.website`)
- ⚠️ เวลาทดสอบ ให้เลือกพอร์ตที่ไม่ชนกับโปรแกรมอื่นในเครื่อง (ช่วง 3200-3220 มีโปรแกรมอื่นใช้อยู่ได้ เช่น EA Desktop) — ถ้าพอร์ตชนกัน เซิร์ฟเวอร์ทดสอบจะสตาร์ทไม่ขึ้นและโปรแกรมจะได้คำตอบแปลก ๆ จากบริการอื่น
- ยังไม่ทำในรุ่นนี้: อัปเดตอัตโนมัติ · สั่งตัดกระดาษ/กระดิ่งผ่านคำสั่ง ESC/POS ดิบ · ใบรับรอง code signing

- ⚠️ **บทเรียนสำคัญ (แก้แล้ว)**: คำขอที่ handler โยน error จะ "ค้างไม่ตอบกลับ" ถ้าไม่ห่อ handler แบบ async — เจอจริงเมื่อแก้ชื่อตัวเลือกอาหารแล้ว SQL ฟ้อง `Column 'name' in field list is ambiguous` (ต้องเขียน `oi.name` เพราะ `option_items` กับ `option_groups` มีคอลัมน์ชื่อซ้ำกัน) ตอนนี้ทุกเราเตอร์ใช้ `src/lib/router.js` (makeRouter) ที่ส่ง error ต่อให้ Express ตอบ 500 แทนการค้าง — เวลาเพิ่มไฟล์เส้นทางใหม่ให้ใช้ `makeRouter()` แทน `express.Router()`

## 🔒 ความปลอดภัย
- รหัสผ่านแฮชด้วย **bcrypt** (cost 10) — ไม่เก็บ plain text
- session ด้วย token สุ่ม + คุกกี้ httpOnly SameSite=Lax
- honeypot + ตรวจเวลากรอกฟอร์ม + rate limit ต่อ IP กันบอท
- รองรับ Google reCAPTCHA v2
- **ไฟล์ที่อาจมีข้อมูลส่วนบุคคลแยกออกจากพื้นที่สาธารณะ** — สลิปโอนเงินเก็บใน `private_uploads/slips/` (นอกโฟลเดอร์ `public/`) เปิดดูได้เฉพาะเจ้าของสลิปนั้นและผู้ดูแลระบบ ผ่าน `GET /api/payments/slip/:name` (ตรวจสิทธิ์ทุกครั้ง · ไฟล์เก่าที่เคยอยู่ใน `public/uploads/slips/` จะถูกย้ายออกให้อัตโนมัติตอนบูต) ส่วนรูปที่ตั้งใจให้สาธารณะ (โลโก้ร้าน/รูปเมนู) ยังอยู่ที่ `public/uploads/shops/`

## 📋 PDPA / ความเป็นส่วนตัว (สิ่งที่ระบบทำไว้แล้ว)
- **หน้าถ้อยแถลงฉบับเต็ม** `/privacy.html` — ระบุผู้ควบคุมข้อมูล, ข้อมูลที่เก็บ (แยกตามกลุ่มผู้ใช้), วัตถุประสงค์ + ฐานทางกฎหมาย, ระยะเวลาเก็บ, การเปิดเผยให้บุคคลที่สาม (โฮสติ้ง/Telegram/Google/SMS-อีเมล/ผู้ตรวจสลิป), มาตรการความปลอดภัย, สิทธิของเจ้าของข้อมูล + วิธีใช้จริง, คุกกี้, ผู้เยาว์, การแจ้งเหตุละเมิด 72 ชั่วโมง, ช่องทางติดต่อ + ช่องทางร้องเรียน สคส. และข้อกำหนดการใช้บริการ
- **ตั้งชื่อผู้ให้บริการ/อีเมลติดต่อได้จากหลังบ้าน** — เมนู **ข้อมูลทางกฎหมาย (PDPA)** `/admin/legal.html` (เจ้าของระบบเท่านั้น) มีตัวอย่างข้อความที่จะขึ้นจริงในหน้าถ้อยแถลงให้เห็นก่อนบันทึก และเตือนชัดเจนถ้ายังไม่ได้ตั้งอีเมล · หน้าภาพรวม (`/admin/`) สรุปค่าให้เห็น + ปุ่มลัดไปหน้าตั้งค่า · ค่าเก็บใน `settings` (`legal_operator`, `legal_email`) และอ่านผ่าน `GET /api/public/legal` โดยถอยไปใช้ `LEGAL_OPERATOR` / `LEGAL_EMAIL` ใน `.env` เฉพาะเมื่อหลังบ้านยังไม่ได้ตั้ง — **ไม่หยิบ `ADMIN_EMAIL` มาแสดงแทน** เพราะอาจเป็นอีเมลที่ไม่มีคนเปิดอ่าน ถ้าไม่มีอีเมลจริง หน้าถ้อยแถลงจะซ่อนบรรทัดอีเมลแล้วบอกให้ใช้ช่องทางติดต่อจากหน้าเว็บแทน
- **บันทึกความยินยอมเป็นหลักฐาน** — ตอนสมัคร (ทั้งทางอีเมลและ Google) ระบบบังคับให้ยอมรับก่อน และบันทึกลง `users.terms_accepted_at` + `users.terms_version` (เวอร์ชันนโยบายอยู่ใน `src/lib/legal.js` — แก้เนื้อหานโยบายแล้วให้อัปเดตค่านี้)
- **สิทธิของเจ้าของข้อมูลทำได้เอง** — `/settings/privacy`: ดาวน์โหลดสำเนาข้อมูล (JSON) · ลบบัญชีถาวร · ดูสถานะความยินยอม
- **สิ่งที่ต้องทำต่อในฐานะผู้ให้บริการ (งานกระบวนการ ไม่ใช่โค้ด)**: กรอกอีเมลติดต่อจริงที่ `/admin/legal.html` (ห้ามปล่อยว่าง ไม่งั้นผู้ใช้ไม่มีช่องทางใช้สิทธิทางเมล) · กำหนดระยะเวลาเก็บข้อมูลจริงให้สอดคล้องข้อ 4 · ฝึกซ้อมขั้นตอนแจ้งเหตุละเมิดภายใน 72 ชั่วโมง (สคส.) · แจ้งผู้ใช้เมื่อเปลี่ยนนโยบายฉบับสำคัญและขอความยินยอมใหม่ · หากมีข้อมูลส่วนบุคคลปริมาณมาก/เป็นกิจจลักษณะ ควรพิจารณาแต่งตั้งเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) และให้ทนายตรวจถ้อยแถลงอีกครั้ง
- **หมายเหตุ**: นโยบายนี้เป็นถ้อยแถลงของแพลตฟอร์ม ส่วนข้อมูลลูกค้าที่ร้านเก็บผ่านระบบ (บิล/ออเดอร์) ร้านเป็นผู้ควบคุมข้อมูลเอง — ระบุไว้แล้วในข้อ 1 ของหน้า
